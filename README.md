# BlobSpawn

Generate exact-size test files directly in your browser. Nothing is uploaded to any server.

Supports **TXT**, **JSON**, **CSV**, and **PDF** (with raster image, custom text, source hyperlink, and optional password-based security). PDFs can be generated by page count or by exact final byte size.

## Tech stack

- **Next.js 16** (static export — `output: "export"`)
- **React 19**
- **Tailwind CSS v4**
- **shadcn/ui** (Base UI)
- **pdf-lib** (client-side PDF generation)
- **qpdf-run** (WASM) (PDF encryption & verification)
- **TypeScript**

## Key features

- All processing happens in the browser — no server requests
- Exact byte size: TXT, JSON, and CSV files are padded with repeating patterns up to the requested size
- PDF by pages (1–1,000) or by final size (with structural padding)
- Custom text in PDFs treated as literal (max 500 characters, 2,000 UTF-8 bytes)
- Optional AES-256 encryption (via qpdf), fixed test passwords, and 10 configurable restrictions
- Large file confirmation (> 500 MB)
- Internationalization: Spanish and English with automatic browser detection and manual selector

## 📋 Pull Request Guidelines

To maintain a clean history and speed up the review process, all Pull Requests **must** follow the standardized structure below.

### 1. Summary
Provide a high-level overview. Answer **what** this PR does and **why** it is needed. Keep it concise—this is your elevator pitch for the change.

### 2. What's included
List every technical detail comprehensively. Be explicit:
- New features, modified components, or removed code.
- **Constraints and edge cases** (e.g., character limits, mutually exclusive modes, supported file sizes).
- Security boundaries (e.g., "executed client-side", "sanitized inputs").
> Use bullet points for clarity. If it's a limit or a rule, write it down here.

### 3. Validation
Prove that the code works and doesn't break existing functionality. Include:
- The exact commands you ran (e.g., `npm test`, `npm run build`, `npm run lint`).
- Specific tools or scripts used for verification.
- Manual testing steps if applicable.
- Always end with a clear confirmation: *"All tests are passing."*

### 4. Base branch
Explicitly state the target branch for this PR (e.g., `main`, `develop`, `release/v1.0`). This removes any ambiguity about the merge destination.
