# pdf-security-permissions Specification

## Purpose

Esta capacidad permite generar PDFs locales con restricciones de seguridad seleccionables, manteniendo documentos sin restricciones por defecto y haciendo explícitas las limitaciones de compatibilidad del estándar PDF.

## Requirements

### Requirement: Optional PDF security mode
The system SHALL generate PDFs without security restrictions by default. The PDF form SHALL provide a single security activation checkbox, and security processing SHALL occur only when that checkbox is enabled.

#### Scenario: Default unrestricted PDF
- **WHEN** the user selects PDF without activating security
- **THEN** the generated document remains compatible with the current unrestricted PDF behavior and no encryption dictionary is added

#### Scenario: Enable security
- **WHEN** the user activates PDF security
- **THEN** the form shows the available security permission checkboxes and the generated PDF is processed with the selected restrictions

### Requirement: Selectable security restrictions
The system SHALL expose one checkbox for each of the following user-visible restrictions: Printing, Changing the document, Document assembly, Content copying or extraction, Content extraction for accessibility, Page extraction, Commenting, Filling of form fields, Signing, and Creation of template pages. All restriction checkboxes SHALL be disabled by default, meaning that no listed restriction is active.

#### Scenario: No restrictions selected
- **WHEN** security is enabled and the user leaves every restriction checkbox disabled
- **THEN** the output allows all representable capabilities and does not activate any listed restriction, subject to mandatory PDF-standard behavior such as accessibility handling

#### Scenario: Individual restriction selection
- **WHEN** the user enables one or more restriction checkboxes
- **THEN** the output denies those capabilities while preserving the selected restriction state for the current generation

#### Scenario: Overlapping PDF restrictions
- **WHEN** the user selects restrictions whose PDF representation shares a bit or is derived from another capability
- **THEN** the system applies the closest representable standard profile and communicates that the selected labels are not independent restrictions in every PDF reader

### Requirement: Display fixed security credentials
The system SHALL use the fixed default credentials `owner-password` and `user-password` when security is enabled and SHALL display them in the security form. The user SHALL NOT be required to enter custom password values.

#### Scenario: Security credentials shown
- **WHEN** the user enables security
- **THEN** the interface displays the owner and user password values that will be used for the generated PDF

#### Scenario: Credentials are not persisted
- **WHEN** the user changes file types or leaves the page
- **THEN** the application does not persist the displayed credentials in a server, database, or browser storage

### Requirement: Explain permission limitations
The system SHALL communicate that PDF permissions are cooperative reader restrictions and are not a DRM or irreversible access-control mechanism. It SHALL identify accessibility extraction as always or generally permitted in modern PDF revisions when the selected encryption revision cannot reliably restrict it.

#### Scenario: Reader-dependent enforcement
- **WHEN** security is enabled
- **THEN** the form explains that compliant readers may enforce restrictions but software can ignore them

#### Scenario: Accessibility permission
- **WHEN** the user attempts to disable content extraction for accessibility
- **THEN** the interface shows an inline warning that modern PDF readers generally keep accessibility extraction allowed and does not claim a universal accessibility restriction

### Requirement: Preserve content and local privacy after security processing
The system SHALL apply security locally to the generated bytes and SHALL preserve the generated pages, image, literal text, fixed source hyperlink, MIME type, and filename behavior. No PDF input, text, password, or generated bytes SHALL be sent to a server.

#### Scenario: Protected content remains readable with credentials
- **WHEN** a secured PDF is opened using the configured user password in a compatible reader
- **THEN** the document contains the expected pages, image, text, and fixed source hyperlink

#### Scenario: No network processing
- **WHEN** the user generates a secured PDF
- **THEN** the browser performs generation and security processing without an API request

### Requirement: Verify secured PDF output before download
The system SHALL verify that a secured result is a structurally valid PDF, contains an encryption/security configuration consistent with the selected profile, and has the expected page and content characteristics before downloading it. On verification failure, the system SHALL report an error and SHALL NOT download the result.

#### Scenario: Valid secured output
- **WHEN** security processing and verification complete successfully
- **THEN** the verified secured Blob is downloaded using the existing local download flow

#### Scenario: Security verification failure
- **WHEN** the processed bytes are invalid, do not contain the requested security configuration, or cannot be validated
- **THEN** generation fails visibly and no misleading download or success state is produced
